### 4.1. Пара 1 — проект, приложение, первое представление

Проект и приложение созданы командами:

```bash
django-admin startproject mysite .
python manage.py startapp core
```

Приложение `core` зарегистрировано в `INSTALLED_APPS`. Реализована view-функция `home`, возвращающая `HttpResponse` с текстом «Hello, Django!», и подключён маршрут:

```python
# core/views.py
def home(request):
    return HttpResponse(
        '<h1>Hello, Django!</h1>'
        '<p><a href="/movies/">Перейти к афише кинотеатра</a></p>'
    )
```

```python
# mysite/urls.py
urlpatterns = [
    path('admin/', admin.site.urls),
    path('', include('core.urls')),
]
```

Для работы в Replit в `settings.py` добавлены (п. 5.4 методических указаний):

```python
ALLOWED_HOSTS = ['*']

CSRF_TRUSTED_ORIGINS = [

```

Сервер запускается на всех интерфейсах: `python manage.py runserver 0.0.0.0:8000`.

### 4.2. Пара 2 — модель, миграции, админ-панель

Модель варианта 1 (`core/models.py`):

```python
class Movie(models.Model):
    title = models.CharField('Название', max_length=200)
    genre = models.CharField('Жанр', max_length=100, blank=True)
    duration_min = models.PositiveIntegerField('Длительность, мин')
    rating = models.DecimalField('Рейтинг', max_digits=3, decimal_places=1, default=0)
    release_year = models.PositiveIntegerField('Год выхода')

    class Meta:
        verbose_name = 'фильм'
        verbose_name_plural = 'фильмы'
        ordering = ['title']

    def __str__(self):
        return self.title

    def get_absolute_url(self):
        return reverse('movie_detail', args=[self.pk])
```

Поле `rating` описано как `DecimalField(max_digits=3, decimal_places=1)` — десятибалльная шкала с одним знаком после запятой (например, `8.6`). Дополнительно у модели есть свойство `duration_pretty`, переводящее минуты в формат «2 ч 49 мин» для шаблонов.

Миграции: `python manage.py makemigrations` сформировал `core/migrations/0001_initial.py`, `python manage.py migrate` применил его к SQLite.

Регистрация модели в админке (`core/admin.py`):

```python
@admin.register(Movie)
class MovieAdmin(admin.ModelAdmin):
    list_display = ('title', 'genre', 'release_year', 'duration_min', 'rating')
    list_filter = ('genre', 'release_year')
    search_fields = ('title', 'genre')
    list_editable = ('rating',)
    ordering = ('title',)
```

В базу внесено 8 записей (больше требуемых 5). Чтобы данные не терялись при пересоздании БД, они сохранены в фикстуре `core/fixtures/movies.json` и загружаются командой `python manage.py loaddata movies`.

### 4.3. Пара 3 — шаблоны и отображение данных

Создан базовый шаблон `core/templates/core/base.html` с шапкой, меню и блоком `{% block content %}`; остальные шаблоны наследуются от него через `{% extends "core/base.html" %}`.

Список и карточка объекта реализованы через generic-классы:

```python
class MovieListView(ListView):
    model = Movie
    template_name = 'core/movie_list.html'
    context_object_name = 'movies'

    def get_queryset(self):
        queryset = super().get_queryset()
        query = self.request.GET.get('q', '').strip()
        if query:
            queryset = queryset.filter(title__icontains=query)
        return queryset


class MovieDetailView(DetailView):
    model = Movie
    template_name = 'core/movie_detail.html'
    context_object_name = 'movie'
```

В `movie_list.html` данные выводятся таблицей через `{% for movie in movies %}`, каждая строка ссылается на детальную страницу по `{% url 'movie_detail' movie.pk %}`. Дополнительно реализован поиск по названию через GET-параметр `q`.

Оформление подключено статическим файлом `static/css/style.css` через `{% load static %}` и `STATICFILES_DIRS`.

### 4.4. Дополнительное задание — форма создания объекта

Реализованы `ModelForm` (`core/forms.py`) и `CreateView` (`/movies/add/`) с CSRF-токеном и валидацией рейтинга (0–10) и года выхода (не раньше 1895): фильмы, добавленные через форму на сайте, сразу появляются в афише — без обращения к `/admin/`.

## 6. Ответы на контрольные вопросы

**Блок 1**

1. **Чем отличается «проект» от «приложения»?** Проект — конфигурация сайта целиком: настройки (`settings.py`), корневая маршрутизация (`urls.py`), точки входа WSGI/ASGI. Приложение — самостоятельный модуль с конкретной функциональностью (модели, представления, шаблоны). Один проект включает несколько приложений, а приложение можно переиспользовать в другом проекте.
2. **За что отвечает `urls.py` и что делает `include()`?** `urls.py` сопоставляет URL-адрес с view: список `urlpatterns` перебирается сверху вниз до первого совпадения. `include()` подключает набор маршрутов другого модуля, отрезая уже разобранный префикс пути, — благодаря этому приложение хранит свои маршруты у себя, а проект лишь монтирует их по нужному префиксу.
3. **Почему на Replit возникает `DisallowedHost` и как её устранить?** Django сверяет заголовок `Host` запроса со списком `ALLOWED_HOSTS`; Replit отдаёт приложение на публичном домене `*.replit.dev`, которого в пустом списке нет, — запрос отклоняется. Решение: добавить выданный домен в `ALLOWED_HOSTS` (в учебных целях допустимо `['*']`). Дополнительно для работы форм нужен `CSRF_TRUSTED_ORIGINS`, иначе POST-запросы падают с «CSRF verification failed».

**Блок 2**

4. **Что будет, если изменить модель и не выполнить `makemigrations`/`migrate`?** Схема таблицы в БД останется старой, а Python-код будет ожидать новую — при обращении к изменённому полю возникнет ошибка уровня базы (`OperationalError: no such column`). Django также предупредит о наличии непримененных изменений моделей.
5. **Какие параметры `ModelAdmin` использованы?** `list_display` — колонки в списке записей; `list_filter` — панель фильтров справа; `search_fields` — поля, по которым работает строка поиска; `list_editable` — поля, редактируемые прямо в списке; `ordering` — сортировка по умолчанию.
6. **Чем миграция отличается от прямого изменения таблицы?** Миграция — версионируемый Python-файл, который хранится в репозитории, применяется одинаково на всех машинах, знает свою зависимость от предыдущих миграций и может быть откачен. Ручной `ALTER TABLE` не фиксируется в истории проекта и рассинхронизирует состояние БД с кодом моделей.

**Блок 3**

7. **Разница между функциональными view и generic-классами?** Функциональная view — обычная функция «запрос → ответ», всё поведение пишется явно. Generic-классы (`ListView`, `DetailView`, `CreateView`) уже содержат типовую логику — выборку queryset, пагинацию, получение объекта по `pk`, обработку формы, — и настраиваются атрибутами (`model`, `template_name`, `context_object_name`) или переопределением методов (`get_queryset`, `get_context_data`). Классы короче для типовых задач, функции нагляднее для нестандартной логики.
8. **Как работает наследование шаблонов?** Базовый шаблон описывает общую разметку и оставляет «дыры» — `{% block %}`. Дочерний шаблон первой строкой указывает `{% extends "core/base.html" %}` и заполняет только нужные блоки; всё остальное берётся из родителя. Это устраняет дублирование шапки, меню и подключения CSS.
9. **Как параметры попадают из URL во view и в шаблон?** В маршруте объявляется конвертер, например `path('movies/<int:pk>/', ...)`; Django извлекает значение, приводит к типу и передаёт во view (для CBV — в `self.kwargs`). `DetailView` по `pk` достаёт объект из БД и кладёт его в контекст под именем из `context_object_name`, после чего шаблон обращается к нему как `{{ movie.title }}`.

## 7. Выводы

В ходе работы развёрнуто полноценное Django-приложение: настроен проект `mysite` и приложение `core`, реализована модель `Movie` по варианту 6, выполнены миграции, настроена административная панель и заполнена база (8 записей), созданы шаблоны с наследованием, страницы списка и карточки объекта, подключён статический CSS. Дополнительно реализована форма создания объекта на основе `ModelForm` и `CreateView`, а также поиск по названию.

Основные трудности и их решения:

* **`DisallowedHost` при открытии webview.** Replit публикует приложение на домене `*.replit.dev`, отличном от `localhost`; исправлено заданием `ALLOWED_HOSTS = ['*']` (учебное упрощение).
* **`CSRF verification failed` при отправке формы добавления фильма.** Домен Replit не входил в список доверенных источников; добавлен `CSRF_TRUSTED_ORIGINS` с шаблонами `https://*.replit.dev` и `https://*.repl.co`.
* **Сервер не виден снаружи при запуске `runserver` без аргументов.** По умолчанию Django слушает только `127.0.0.1`; нужен запуск на `0.0.0.0:8000`.
* **Потеря данных при пересоздании БД.** Тестовые записи вынесены в фикстуру `core/fixtures/movies.json`, база восстанавливается парой команд `migrate` + `loaddata movies`.
* **Нестабильный интерактивный ввод пароля в консоли Replit.** Суперпользователь создавался неинтерактивно, через переменные окружения `DJANGO_SUPERUSER_*` и флаг `--noinput`.
